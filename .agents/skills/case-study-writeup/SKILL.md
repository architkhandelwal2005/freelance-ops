# case-study-writeup

Use with `delivery-standards` for any assigned paid job. Work from Claude's job file, not from assumptions.

## Intake
Require Approved job outcome, public-use permission, client-approved name/logo, metrics evidence and redaction limits. If a field is absent, put the precise question in the job file under `## Questions` for Claude. Do not fill missing client facts from search.

## Method and default stack
Default no-cost stack: Markdown page and local image optimization; publish only after Claude approval.

1. Confirm public-use setting and exact approved identifiers.
2. Extract problem, scope, work and observed outcome from job evidence.
3. Write concise story with uncertainty where results are unmeasured.
4. Redact private screenshots/data and check every claim.
5. Prepare review page and source/permission log.

## Time guide
Small 2-4 h; medium 1 day; large 2+ days after approvals. These are internal effort guides, not client commitments.

## QA: pass criteria
- [ ] Public-use permission documented.
- [ ] All metrics have evidence.
- [ ] No confidential detail or invented testimonial.
- [ ] Story accurately reflects delivered scope.
- [ ] Claude approval precedes publication.

Save the evidence in the job folder; a claim of "tested" without results does not pass. Use [checklist.md](checklist.md) to record the checks.

## Deliverables and handover pack
Markdown case study, sanitized assets, evidence map, permission log and walkthrough script. Include a plain-language `handover.md` with run/update steps, files, limits, backup location and a 60-second walkthrough script.

## Escalate to Claude when
No public-use permission, disputed result, identifiable private data or publish request. Record the question in the job file and stop the dependent action.

## Never
Never contact anyone or send client-facing work directly; Claude reviews and delivers. Never spend money or sign up as Archit; use no-cost tools first. Never invent clients, claims, results or experience; mark unknowns [TO CONFIRM]. Describe Archit as building with AI tools and checking every change by hand, never as hand-coding. Never confirm price, deadline or scope. Back up sites and work only on staging without written live-production go-ahead. Keep client data private; public samples use fictional brands. Do not put “free” in client-facing copy. Do not make unsupported medical, legal or financial claims.

For a fictional test brief, use [prompt.md](prompt.md).

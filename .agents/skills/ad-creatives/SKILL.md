# ad-creatives

Use with `delivery-standards` for any assigned paid job. Work from Claude's job file, not from assumptions.

## Intake
Require Approved product facts, audience, channel specs, offer, brand assets, legal restrictions and test goal. If a field is absent, put the precise question in the job file under `## Questions` for Claude. Do not fill missing client facts from search.

## Method and default stack
Default no-cost stack: SVG/PNG design from local tools; editable copy sheet and storyboard.

1. Select one audience pain and approved benefit.
2. Draft distinct hooks, body copy and calls to action.
3. Build static variations and short video shot list.
4. Check crop, legibility, accessibility and asset licences.
5. Package export sizes and test matrix without performance promises.

## Time guide
Small 3-6 h; medium 1-2 days; large 3-5 days after approvals. These are internal effort guides, not client commitments.

## QA: pass criteria
- [ ] Claims map to approved facts.
- [ ] Text readable on mobile crop.
- [ ] No unlicensed visuals.
- [ ] Variants differ in one testable idea.
- [ ] Files match requested dimensions.

Save the evidence in the job folder; a claim of "tested" without results does not pass. Use [checklist.md](checklist.md) to record the checks.

## Deliverables and handover pack
Editable concepts, PNG/SVG exports, copy matrix, shot list, licence log and walkthrough script. Include a plain-language `handover.md` with run/update steps, files, limits, backup location and a 60-second walkthrough script.

## Escalate to Claude when
Paid assets, regulated claims, platform rejection or offer changes. Record the question in the job file and stop the dependent action.

## Never
Never contact anyone or send client-facing work directly; Claude reviews and delivers. Never spend money or sign up as Archit; use no-cost tools first. Never invent clients, claims, results or experience; mark unknowns [TO CONFIRM]. Describe Archit as building with AI tools and checking every change by hand, never as hand-coding. Never confirm price, deadline or scope. Back up sites and work only on staging without written live-production go-ahead. Keep client data private; public samples use fictional brands. Do not put “free” in client-facing copy. Do not make unsupported medical, legal or financial claims.

For a fictional test brief, use [prompt.md](prompt.md).
